# Express forks and Express-compatible rewrites: what they changed, and what Express 6 could take

Written 2026-11-21. Baseline: Express 5.3.0 at upstream `master` commit [43fca52d](https://github.com/expressjs/express/commit/43fca52d28a422c8be48fd489cbd4f2d6152bab6), router 2.3.0. Every speedup below is the project's own claim unless it says otherwise. No benchmarks were run for this note.

## Short answer

- Almost none of the forks of `expressjs/express` have meaningful changes. Of 428 forks compared against upstream, 161 have commits upstream lacks, and 28 of those touch `lib/` or `index.js`. Only one of the 28 is a serious engineering fork: [EriksRemess/express](https://github.com/EriksRemess/express) (73 commits ahead). It brings every dependency into the repo, requires Node 26 and ESM, adds a static-route index to the router, and has a long list of security fixes. The rest are homework, CI experiments, single feature patches, or automated rewrites.
- The useful ideas come from the rewrites: [ultimate-express](https://github.com/dimdenGD/ultimate-express) and its Express 5 offshoot [fulmine.js](https://github.com/nigrosimone/fulmine.js). Most of their speed comes from uWebSockets.js, which Express cannot adopt without dropping `node:http`. A few techniques do carry over, and the fulmine author is already sending some upstream ([#7555](https://github.com/expressjs/express/pull/7555), [#7481](https://github.com/expressjs/express/pull/7481)).
- The best safety lesson: every project that added a routing fast path also shipped an authorization bypass in it, then fixed it later ([ultimate-express cc6bf139](https://github.com/dimdenGD/ultimate-express/commit/cc6bf1398af7fbedb702b20eb2389be0e24c42d5), [EriksRemess History.md](https://github.com/EriksRemess/express/blob/master/History.md)). Projects that left `node:http` had to rebuild header validation and request-framing checks by hand ([ultimate-express ace01985](https://github.com/dimdenGD/ultimate-express/commit/ace019854f765b732223eff95430bae2e15c31a7), [fulmine differences](https://github.com/nigrosimone/fulmine.js/blob/main/docs/differences.md)).

## Method

**Fork listing.** `GET repos/expressjs/express/forks` returns at most 100 forks per page. Upstream reports 25,667 forks.

| Sort | Pages read | Forks | Creation dates covered |
| --- | --- | --- | --- |
| `newest` | 1 to 60 | 6,000 | 2025-11-14 to 2026-11-21 |
| `oldest` | 1 to 40 | 4,000 | 2009-12-11 to 2016-12-20 |
| `stargazers` | 1 to 10 | 1,000 | mixed |
| `watchers` | 1 to 10 | 1,000 | mixed |
| **Unique** | | **10,326** (about 40% of all forks) | |

Forks created between 2017 and 2025-11 were only reached through the star and watcher lists. That gap is the main limit of this scan.

**Filter.** 6,180 forks have `pushed_at` on or after 2024-01-01. In most of them, `pushed_at` is just the upstream push time copied over when the fork was made. I kept only forks with a push more than 10 minutes after creation: **441 candidates**.

**Compare.** For each candidate I called `GET repos/expressjs/express/compare/<base>...<owner>:<repo>:<default branch>`, with `master` as the base and `4.x` and `5.x` as fallbacks when the fork looked older. 428 compares worked. 13 failed: 11 returned Not Found, and 2 had no common ancestor because the repo had been replaced with unrelated code. Results:

| Result | Forks |
| --- | --- |
| Not ahead of upstream (`ahead_by` = 0) | 267 |
| Ahead, but only app code, homework or `package.json` | 51 |
| Ahead, only docs, README or examples | 48 |
| Ahead, only CI or config files | 17 |
| Ahead, tests only | 10 |
| Ahead, only merge commits with no file diff | 7 |
| **Ahead and touching `lib/` or `index.js`** | **28** |

I read the commits of all 28 and the patches of the 8 that looked substantive. The scan used about 1,100 API calls. Branches other than each fork's default branch were not scanned.

**Rewrites.** I read READMEs, source and commits through `gh api`, release dates and weekly downloads from the npm registry, and GitHub security advisories through `GET /advisories?ecosystem=npm&affects=<pkg>`. None of the projects below has a published advisory. That does not prove they are safe. I searched npm for "express fork", "fork of express", "express compatible", "drop-in replacement express", "faster express", "express uwebsockets" and "elysia express".

Notes:

- **How ultimate-express reaches compatibility.** Its test runner runs every test file against Express 4, then Express 5, then ultimate-express, and compares the stdout ([tests/index.js](https://github.com/dimdenGD/ultimate-express/blob/main/tests/index.js), about 320 test files). fulmine says it does the same byte-for-byte and also passes Express 5's own test suite ([README](https://github.com/nigrosimone/fulmine.js#why-fulmine); claimed, not checked here).
- **Why its routing fast path is fragile.** A route moves to the native router only if no earlier layer that could match it is a router, and only when `case sensitive routing` is on. The fix in [cc6bf139](https://github.com/dimdenGD/ultimate-express/commit/cc6bf1398af7fbedb702b20eb2389be0e24c42d5) changed `if(pathPrefix)` to `if(router !== this)`. Before that, routes inside a router mounted with no path skipped the app's earlier auth middleware. Its regression test is a 401-check middleware followed by `app.use(router)`.
- **What leaving `node:http` costs.** ultimate-express had to add its own token and CR/LF checks to `setHeader` and `writeHead` in 2026-10 ([ace01985](https://github.com/dimdenGD/ultimate-express/commit/ace019854f765b732223eff95430bae2e15c31a7)). fulmine documents that uWS accepts repeated `Content-Length` headers, non-chunked final `Transfer-Encoding` and lowercase methods, which allows smuggling ([differences](https://github.com/nigrosimone/fulmine.js/blob/main/docs/differences.md)). Node's parser rejects all of these with a 400.

## Ideas portable into Express

Ranked by expected gain against behaviour risk. Several are already open upstream PRs. For those, the forks and rewrites are extra evidence, not new ideas.

1. **Build a test harness that compares responses with the previous Express.** Run every scenario against Express 5.3.0 and against the 6.x branch, and diff status, headers and body bytes. This is the method ultimate-express and fulmine use to stay compatible ([tests/index.js](https://github.com/dimdenGD/ultimate-express/blob/main/tests/index.js)). It is what makes ideas 2 to 6 safe to land. **Risk:** none to runtime behaviour. It is test infrastructure.

2. **Skip the per-request `Object.setPrototypeOf` on req and res when Express created the server.** `app.handle` swaps both prototypes on every request ([application.js L169-L170](https://github.com/expressjs/express/blob/43fca52d28a422c8be48fd489cbd4f2d6152bab6/lib/application.js#L169-L170)). The rewrites avoid the swap by building req and res as instances of classes with the right prototype from the start ([ultimate-express request.js](https://github.com/dimdenGD/ultimate-express/blob/main/src/request.js)). The Express-shaped version passes `IncomingMessage` and `ServerResponse` subclasses to `http.createServer` from `app.listen()`, and skips the swap when the prototype already matches. That is upstream [#7555](https://github.com/expressjs/express/pull/7555) (draft), which claims about 2.4 µs per request, 22% of `app.handle` time, on Node 24 and 26. **Risk:** low. Apps that call `http.createServer(app)` themselves keep the swap and gain nothing. Mounted sub-apps still swap and restore. Note that [perf-wg#15](https://github.com/expressjs/perf-wg/issues/15) blames per-request `defineProperty`, but Express defines its getters only once, on the shared prototype ([request.js L30](https://github.com/expressjs/express/blob/43fca52d28a422c8be48fd489cbd4f2d6152bab6/lib/request.js#L30), [L521](https://github.com/expressjs/express/blob/43fca52d28a422c8be48fd489cbd4f2d6152bab6/lib/request.js#L521)). The real per-request cost is the prototype swap.

3. **Add an order-preserving index for static paths in the router (pillarjs/router).** Today `next()` runs every layer's matcher, in order, for every request ([router v2.3.0 index.js L244-L280](https://github.com/pillarjs/router/blob/v2.3.0/index.js#L244-L280)). EriksRemess groups runs of consecutive literal-path layers into a map from path to layer indexes. It uses the map only when a run has 8 or more layers and its buckets are sparse, and it treats every dynamic or regex layer as a barrier. Registration order is therefore unchanged ([51eb5cbb](https://github.com/EriksRemess/express/commit/51eb5cbb4e39c43e5e44fe0fb09f6606bfd00fde)). ultimate-express gets a similar result by precomputing the chain in front of each static route ([router.js](https://github.com/dimdenGD/ultimate-express/blob/main/src/router.js)). The 7.5x to 17.2x "large route table" figure is fulmine's claim, includes uWS's C++ matcher, and says nothing about a pure-JS index. **Risk:** high. Both implementations needed authorization-bypass fixes. ultimate-express needed [cc6bf139](https://github.com/dimdenGD/ultimate-express/commit/cc6bf1398af7fbedb702b20eb2389be0e24c42d5). EriksRemess lists case, trailing-slash, path-array and stateful-regex bypasses ([History.md](https://github.com/EriksRemess/express/blob/master/History.md)), and later had to "leave the static-route fast path as soon as middleware is registered" and rebuild the plan when handlers are added during dispatch ([bf449f75](https://github.com/EriksRemess/express/commit/bf449f75e7a85ac362003689eccf54ff1c50d6e6)). `router.stack` is public and some apps splice it, so the index must notice changes. The key has to respect `strict`, `caseSensitive` and `end` exactly. Needs idea 1 first.

4. **Remember derived request values for the rest of the request, and recompute when their inputs change.** ultimate-express caches query, headers, subdomains and parsed IP in private fields ([request.js](https://github.com/dimdenGD/ultimate-express/blob/main/src/request.js)). tinyhttp creates the `Accepts` instance lazily ([extend.ts](https://github.com/tinyhttp/tinyhttp/blob/master/packages/app/src/extend.ts)). fulmine memoises content-type lookups. Upstream versions already exist: [#7517](https://github.com/expressjs/express/pull/7517) caches `req.query` until `req.url` or the parser changes, [#7519](https://github.com/expressjs/express/pull/7519) caches trust-proxy results (claims `req.ip` drops from about 2150 ns to 64 ns), [#7008](https://github.com/expressjs/express/pull/7008) caches `accepts`, and [#7481](https://github.com/expressjs/express/pull/7481) memoises content types (claims `setCharset` drops from 470 ns to 11 ns). **Risk:** medium for query, low for the others. Today every `req.query` read returns a new object, so `req.query.x = 1` is lost on the next read. With caching it stays, as #7517 notes. Maintainers closed caching that never recomputed, because getters must reflect changes ([#6042](https://github.com/expressjs/express/pull/6042) comment by krzysdz). The cache has to be keyed on its inputs.

5. **Check the method before running the path regex for route layers.** trouter checks the method first ([trouter `find`](https://github.com/lukeed/trouter/blob/master/index.mjs)). Express runs `layer.match(path)` first and checks `route._handlesMethod` afterwards ([index.js L249, L275](https://github.com/pillarjs/router/blob/v2.3.0/index.js#L249-L280)). This is my own adaptation, not something a fork tested inside Express. Skip the match when the route cannot handle the method, unless the method is OPTIONS (which collects `Allow`) or HEAD (which falls back to GET). **Risk:** low, but not zero. A failed `decodeURIComponent` in a layer of the wrong method currently makes the request a 400 ([layer.js L326](https://github.com/pillarjs/router/blob/v2.3.0/lib/layer.js#L326)). Skipping that layer would turn it into a 404. To keep results identical, skip only when the path contains no `%`.

6. **Add a fast path for the `extended` query parser.** ultimate-express uses `node:querystring` for queries of 128 characters or fewer that contain no `[`, `%5B`, `.` or `%2E`, and `qs` otherwise. It spreads the result into a plain object ([utils.js `fastQueryParse`](https://github.com/dimdenGD/ultimate-express/blob/main/src/utils.js)). Express's extended parser is `qs.parse(str, { allowPrototypes: true })` ([utils.js L267](https://github.com/expressjs/express/blob/43fca52d28a422c8be48fd489cbd4f2d6152bab6/lib/utils.js#L267)). Because `allowDots` is off, the dot checks are not needed in Express. No speed figure was published. **Risk:** medium. The output must match `qs` exactly for malformed percent escapes, `+`, empty keys, repeated keys, the 1000-key limit and the prototype of the result. Run a differential fuzz test against `qs` before adopting it.

7. **Set the default `text/html; charset=utf-8` and `application/json; charset=utf-8` values directly, without a mime lookup.** Upstream [#7516](https://github.com/expressjs/express/pull/7516) claims about 200 ns per response and no change within noise in a full request benchmark. **Risk:** low.

8. **Use null-prototype objects whose prototype is a shared empty object (the "NullObject" trick).** The constructor's prototype is `Object.create(null)`, so instances start in V8's fast-property mode. Used for query and params in ultimate-express ([utils.js](https://github.com/dimdenGD/ultimate-express/blob/main/src/utils.js)). fulmine claims `for...in` gets about 3x cheaper ([differences](https://github.com/nigrosimone/fulmine.js/blob/main/docs/differences.md)). In Express this could apply to objects it creates on every request, such as `res.locals = Object.create(null)` ([application.js L174](https://github.com/expressjs/express/blob/43fca52d28a422c8be48fd489cbd4f2d6152bab6/lib/application.js#L174)). **Risk:** medium. `Object.getPrototypeOf(x)` stops being `null`, so `_.isPlainObject(x)` becomes false. That is observable, so it fits a 6.0 major better than a minor.

Not to port (techniques that change behaviour or weaken safety):

- **Compiling handlers from their source into static responses** ([declarative.js](https://github.com/dimdenGD/ultimate-express/blob/main/src/declarative.js)). It breaks `Connection: close` and `If-None-Match: *`, and it depends on `Function.prototype.toString` ([fulmine differences](https://github.com/nigrosimone/fulmine.js/blob/main/docs/differences.md)).
- **Writing headers or framing responses outside `node:http`.** Node's `setHeader` validation and the llhttp parser are what stopped the response-splitting and smuggling problems the uWS projects had to fix by hand ([ace01985](https://github.com/dimdenGD/ultimate-express/commit/ace019854f765b732223eff95430bae2e15c31a7)).
- **Unbounded route-match caches keyed by request path.** The path is chosen by the client, so such a cache is a memory-exhaustion risk. 0http caps entries and entry size ([sequential.js](https://github.com/BackendStack21/0http/blob/main/lib/router/sequential.js)), and EriksRemess had to "bound route dispatch caches" ([9f3ffca5](https://github.com/EriksRemess/express/commit/9f3ffca55b201b1a02cec7859036476ec5ac4629)).
- **Computing ip, protocol and query on every request, plus per-request closures** (tinyhttp [extend.ts](https://github.com/tinyhttp/tinyhttp/blob/master/packages/app/src/extend.ts)). This is worse than Express's lazy getters on the shared prototype.

## Dead ends

- **Sorting forks by stars or watchers.** The top 1,000 of each are tutorial copies. Even among forks pushed after creation, only 28 of 161 ahead touch library code, and about 6 of those are original work.
- **hanzoai/express**: a mirror plus CI, with nothing original. **Milivitoria/expressts** and **alexgauss/express**: TypeScript ports with no performance or safety goal.
- **shambhu123bcoder/express**: re-applies the `allowPrototypes: false` change that Express reverted in 5.2.1 ([History, CVE-2024-51999](https://github.com/expressjs/express/security/advisories/GHSA-pj86-cfqh-vqx6)).
- **Caching getters forever, or turning getters into plain assignments** ([#6042](https://github.com/expressjs/express/pull/6042), [#6001](https://github.com/expressjs/express/pull/6001)). Both were closed, because getters must reflect later changes.
- **The "defineProperty on every request" theory** in [perf-wg#15](https://github.com/expressjs/perf-wg/issues/15). Express does not do that. See idea 2.
- **npm packages calling themselves an "Express fork".** [neste](https://github.com/Sirherobrine23/neste) is archived and gets 16 downloads a week. `expat` (2017) has no repository.
- **Elysia.** No Express compatibility layer was found on npm. [elysiajs/node-adapter](https://github.com/elysiajs/node-adapter) is archived. **Bun**: Express runs unchanged on Bun's `node:http` ([Bun guide](https://bun.com/guides/ecosystem/express), which makes no speed claim). The "2 to 3 times faster on Bun" figure is ultimate-express's claim.
- **hyper-express**: not drop-in, so it has no Express-shaped technique to borrow.
- **polka**: the only portable piece is checking the method first (idea 5). Everything else comes from dropping Express features.
- **EriksRemess's `send` change that skips the file open**: it removes an open the fork added itself, and upstream `send` already answers 304 and 412 before streaming.
