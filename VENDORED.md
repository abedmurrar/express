# Vendored packages

This fork keeps its own copies of the packages it needs to change. Each one keeps its licence and copyright lines in its folder (MIT, except `qs`, which is BSD-3-Clause). Every change we make to a copy is listed below, so we can re-sync from upstream later.

| Package | Upstream | Version | Upstream commit | Our copy | Tests |
|---|---|---|---|---|---|
| `router` | https://github.com/pillarjs/router | 2.2.0 | `e6d6b60` | `src/router/` | `test/router/` |
| `send` | https://github.com/pillarjs/send | 1.2.1 | `096a6148` | `src/send/` | `test/send/` (plus `test/send/fixtures/`) |
| `serve-static` | https://github.com/abedmurrar/serve-static (our fork of https://github.com/expressjs/serve-static) | 2.2.1 | `76312e12` | `src/serve-static/` | `test/serve-static/` (plus `test/serve-static/fixtures/`) |
| `qs` | https://github.com/ljharb/qs | 6.17.1 | `43baea46` | `src/qs/` | `test/qs/` (plus `test/qs/support/`) |
| `body-parser` | https://github.com/expressjs/body-parser | 2.4.0 | `b4744d73` | `src/body-parser/` | `test/body-parser/` |

Why these five: most of the routing bugs and routing performance work are in `router`. The empty-body bug for `/proc` files (#4944) is in `send`. `serve-static` is vendored so that `express.static` uses our `send` and gets its fixes: with the `send` that the npm package installs, a `setHeaders` function that throws crashes the process.

`qs` is vendored so the extended query parser needs no dependencies: qs's two, `side-channel` (with its chain: `side-channel-list`, `side-channel-map`, `side-channel-weakmap`, `call-bound`, `get-intrinsic` and the rest) and `es-define-property`, are replaced by `WeakMap`, `Map` and `Object.defineProperty`. `body-parser` is vendored so `express.urlencoded({ extended: true })` uses our `qs` too: the npm `body-parser` required the npm `qs`, which kept `side-channel` and its chain installed. With both vendored, a production install has 38 packages instead of 58 (`npm ls --omit=dev --all --parseable` prints 39 lines instead of 59, the first being Express itself): `body-parser`, `qs`, and the 18 packages under `qs` (`side-channel`, `side-channel-list`, `side-channel-map`, `side-channel-weakmap`, `call-bound`, `call-bind-apply-helpers`, `get-intrinsic`, `es-define-property`, `es-errors`, `es-object-atoms`, `function-bind`, `get-proto`, `dunder-proto`, `gopd`, `has-symbols`, `hasown`, `math-intrinsics` and `object-inspect`) are gone.

All five copies are the same versions Express 5.3.0 installs here, and match the installed packages line for line except for the edits listed below.

`serve-static`'s source is our fork, https://github.com/abedmurrar/serve-static, created from expressjs/serve-static with only its default branch. Nothing is pushed to it yet: its `master` is upstream's, and the vendored code is upstream's tag `v2.2.1` (commit `76312e12c2754c226a685201ff43d785455d0590`, which the fork's `master` contains; the fork has no tags). Upstream's `master` has one later change to `index.js`, a comment typo fix (`fall-though` to `fall-through`, expressjs/serve-static#246), which is not released and not in our copy.

`router` 2.3.0 (published 2026-11-17) is not vendored yet. This machine's npm config only accepts releases at least 7 days old, so it waits until 2026-11-24 and goes in as a re-sync. It fixes a rewritten `req.url` losing a slash in a mounted router (upstream issue #4059, pillarjs/router#206), and adds `router.listRoutes()` (pillarjs/router#174) and request tracing channels (pillarjs/router#196).

`express.static` is our `lib/serve-static`, which loads our `lib/send`, so `express.static`, `res.sendFile` and `res.download` all use the same `send`. The `serve-static` package (and the npm `send` it brings) is no longer a dependency; npm still installs both for the development-only `express-baseline` (Express 5.3.0, the differential harness's baseline).

## Changes from upstream

### router

- `src/router/index.js`: added `const { Buffer } = require('node:buffer')` to match Express's lint rule against the global `Buffer`. No behaviour change.
- `src/router/index.js`: renamed two function names so no file has two functions with the same name, which the coverage merge (`lcov` 2) rejects. `Router.prototype.handle` is now `function handleRequest`, and the inner `param` helper in `processParams` is now `nextParam`. Property names are unchanged; only stack-trace frame names differ. The route layer's handler keeps the name `handle`, because tools read it through `layer.name`.

- `src/router/index.js`: the function used as `Router.prototype` is now named `RouterPrototype`, so c8's lcov report doesn't list two functions called `Router`, which breaks the CI coverage merge. It also carries a `/* c8 ignore next */`, because it exists only so routers inherit from `Function` and is never called. Upstream marked it with `istanbul ignore` for the same reason.
- The three files are strict TypeScript: `src/router/lib/layer.ts`, `src/router/lib/route.ts` and `src/router/index.ts`. Only types were added: the statements, their order, the function names and the comments are upstream's, and the compiled `lib/` files differ from the JavaScript build only in the lines below. When re-syncing, apply upstream's JavaScript changes to these files and type the new lines the same way. Dependencies are loaded with `require` and typed with `typeof import(...)`, and the types each file exports (the request and response views, the handler types and the `Layer`, `Route` and `Router` interfaces) are declared after the `require` lines. `RouterRequest` and `RouterResponse` are aliases of Express's `Request` (`src/request`) and `ExpressResponse` (`src/response`), imported with `import type`, so the compiled router still requires nothing from Express. The lines that read differently from upstream:
  - `layer.ts`: the prototype methods are assigned through `const proto = Layer.prototype as Layer` (`proto.handleError = ...` instead of `Layer.prototype.handleError = ...`), because a function declaration's `prototype` is untyped. The no-`new` call is `new (Layer as LayerConstructor)(path, options, fn)`. `err.status = 400` in `decodeParam` is written `;(err as URIError & { status: number }).status = 400`. `decodeParam` and `loosen` gained overload signatures, so their JSDoc comments sit above those.
  - `route.ts`: the prototype methods are assigned through `const proto = Route.prototype as Route`, including the generated ones (`proto[method] = function (handler) {...}`). `methods` is cast to the `HttpMethod` union. The flattened handler lists are declared `unknown[]`, and each handler is passed to `Layer` as `fn as LayerHandler` after the existing `typeof fn !== 'function'` check. A few indexed reads carry a cast where the loop bounds already guarantee the value (`stack[idx++] as LayerInstance`, `methods[i] as string`, `this.methods[name as string]`).
  - `index.ts`: the prototype methods are assigned through `const proto = Router.prototype as Router`, which comes right after `Router.prototype = function RouterPrototype() {}` (its `istanbul` and `c8 ignore` comments are unchanged). The no-`new` call is `new (Router as RouterConstructor)(options)`. Inside `Router`, the inner `router` function is cast where TypeScript can't see its prototype: `;(router as Router).handle(req, res, next)` (Biome adds the leading `;`, which compiles to an empty statement), `router.stack = [] as LayerInstance[]` and `return router as Router`. `methods` is cast to `Array<HttpMethod | 'all'>`. `processParams` declares `key`, `paramVal`, `paramCallbacks` and `paramCalled` with their set types and casts them where `nextParam` assigns them, because `paramCallback` reads them from a closure. `req.params` gets `layer.params as Params` and `layerPath` gets `layer.path as string` (both set once the layer matched). `getPathname` casts the `parseurl` result to `Url`, keeping upstream's `try`/`catch`. `restore` gained an overload signature (so its JSDoc comment sits above it) and builds its arrays with `new Array<K>(...)` and `new Array<T[K]>(...)`, which compile to the same `new Array(...)`.

- `src/router/lib/layer.ts`: the RegExp matcher sets `lastIndex = 0` before `exec` when the RegExp has the `g` or `y` flag (`const stateful = _path.global || _path.sticky`), so a stateful RegExp path matches on every request instead of every other one. Not in upstream (router 2.2.0); check router 2.3.0 for its own fix when re-syncing.

- `src/send/index.js`: `SendStream.prototype.error` no longer falls back to `String(status)` when a status has no standard message. Every caller passes 400, 403, 404, 412, 416 or 500, so the fallback could never run.

- `src/send/index.js`: `SendStream.prototype.send` wraps `this.setHeader(path, stat)` in a try/catch and passes a throw to `this.error(500, err)`. A throwing `headers` listener (for example Express's `res.sendFile` `headers` option with a CR or LF in a value) used to be an uncaught exception, because it runs in an `fs.stat` callback. Not in upstream.
- The file is strict TypeScript: `src/send/index.ts`. Only types were added: the statements, their order, the `var` declarations, the function names and the comments are upstream's (with the edits above). When re-syncing, apply upstream's JavaScript changes to this file and type the new lines the same way.   - `send`: `new (SendStream as unknown as SendStreamConstructor)(req, path, options)`, because `SendStream` is only ever called with `new`.

  - The prototype methods are assigned through `const proto = SendStream.prototype as SendStream`, which comes right after `util.inherits(SendStream, Stream)`.

  - `pipe`: `var parts: string[]`.
  - `send` (`sendPath`): `var opts: SendOptions = {}`, `var ranges: string | undefined | RangeResult | Ranges = req.headers.range`, `this.error(500, err as Error)` in our try/catch, `BYTES_RANGE_REGEXP.test(ranges as string)`, `parseRange(len, ranges as string, {`, and `(ranges[0] as Range)` in the two lines that adjust `offset` and `len`.

  - `containsDotFile`: `var part = parts[i] as string`. `setHeaders`: `var key = keys[i] as string` and `headers[key] as OutgoingHttpHeader`.

  - Every other line gained parameter and return types only.

### qs

The source is upstream's tag `v6.17.1` (commit `43baea4655cb9b543fb1c5cc0db95cde42852140`), whose `lib/` files are identical to the npm package's. `src/qs/LICENSE` is upstream's `LICENSE.md` (BSD-3-Clause), copied into `lib/qs/` by `scripts/build.js`.

Dependencies replaced with what Node 22 has:

- `side-channel` (and its chain), everywhere qs made a channel:
  - `src/qs/utils.ts`: `overflowChannel` and `conflictChannel` (module-level, so they must not keep parsed objects alive), the `ancestors` map in `toCoercible` and `refs` in `compact` are `new WeakMap()`. Every key they are given to store is an object or an array. `isOverflow` is also called with strings and numbers, for which `WeakMap.prototype.has` returns `false`, as `side-channel` did (it never stored them).
  - `src/qs/parse.ts`: `copies` in `copyInput` is `new WeakMap()` (keyed by arrays and plain objects only).
  - `src/qs/stringify.ts`: the cycle-detection channels (`sideChannel` and `valueSideChannel`) are `new Map()`, not `WeakMap`. Each level's channel maps the value being stringified to its step, and `sentinel` to the parent level's channel. The lookups (`tmpSc.get(sentinel)`, `tmpSc.get(object)`, `sideChannel.set(object, step)`) are upstream's, so the same `RangeError('Cyclic object value')` is thrown at the same point. The key is the value before `filter` runs, so it is a primitive when a `filter` turns a primitive into an object. `side-channel` kept such keys in a `Map`; a `WeakMap` throws `TypeError: Invalid value used as weak map key` there. For example, `qs.stringify({ a: 'x' }, { filter: (p, v) => p === 'a' ? { b: 1 } : v })` gives `a%5Bb%5D=1` with upstream and with a `Map`, and throws with a `WeakMap`. A `Map` compares keys the same way `side-channel` did (`SameValueZero`), and these channels only live for one `stringify()` call. `test/qs/fork-additions.js` and the property test cover it.
- `es-define-property` is `Object.defineProperty` (`var defineProperty = Object.defineProperty`). `setProperty` keeps upstream's `key === '__proto__' && defineProperty` check, which is now always true.

The files are strict TypeScript with no `any`: `src/qs/index.ts`, `formats.ts`, `parse.ts`, `stringify.ts` and `utils.ts`. Only types were added: the statements, their order, the `var` declarations, the function names and the comments are upstream's (with the edits above). When re-syncing, apply upstream's JavaScript changes to these files and type the new lines the same way. Each file loads the others with `require`, typed by the type each one exports for its `module.exports` (`Formats`, `Utils`, `ParseFunction`, `StringifyFunction` and `Qs`), and checks its own `module.exports` object with `satisfies`, which compiles away. The other exported types are `FormatName`, `Formatter`, `ParseOptions`, `ParsedQs`, `Decoder`, `StringifyOptions`, `Encoder`, `QsRecord` (an object read by key), `MergeOptions`, `EncodeFunction` and `DecodeFunction`. Values qs reads dynamically are `unknown`, and are narrowed or cast where they're used. The lines that read differently from upstream:
  - All files: `var isArray = Array.isArray as (value: unknown) => value is unknown[]`, so a narrowed value is `unknown[]` rather than `any[]`. Indexed reads that the loop bounds guarantee are cast (`keys[i] as string`, `parts[i] as string`, `chain[i] as string`, `queue[i] as CopyItem`, `queue.pop() as QueueItem`).
  - `formats.ts`: `replace` is cast to `(this: unknown, searchValue: RegExp, replaceValue: string) => string`, because a formatter is also given what a custom encoder returns. `Format` is `as const`.
  - `utils.ts`: `markOverflow` and `markConflict` are generic (they return the object they're given), `isOverflow` is a type predicate (`overflowChannel.has(obj as object)`), and `getMaxIndex` and `getConflictIndex` cast the stored index `as number`. In `merge`, the writes to an object target are `(target as QsRecord)[...]`, the prototype check is `has.call(Object.prototype, source as PropertyKey)`, `mergeTarget` starts as `target as QsRecord`, and the reduce callback reads `(source as QsRecord)[key]` (the same in `assign`). `toCoercible` reads `(value as { [Symbol.toPrimitive]?: unknown })[Symbol.toPrimitive]`. `encode` checks `(str as { length?: unknown }).length === 0` and starts from `var string = str as string`, and the first `hexTable[...]` of each sum is cast `as string`. `isBuffer` reads `(obj as BufferLike).constructor`. `combine` builds `([] as unknown[]).concat(a, b)`. `compact` casts `item.obj[item.prop] as QsRecord`. `decode`'s unused catch binding is `catch {}`, as in the other copies.
  - `parse.ts`: the decoded key is `var key: PropertyKey | null`, with each decoder result cast to it, and an existing array value is read as `(obj[key] as unknown[]).length`. A value passed to the decoder is cast `as string`. In `parseObject`, `(val as unknown as QsRecord)[parentKey]` (an array read by a string key) and `var obj: QsRecord | unknown[]`. `parse()` casts the results of `utils.merge` and `utils.compact` `as QsRecord`.
  - `stringify.ts`: `comma: 'comma' as const`. The channel walk reads `(tmpSc as Channel).get(sentinel) as Channel | undefined`. The comma join reads `(obj as unknown[]).length` and `utils.toCoercible(obj) as unknown[]`; the key list is `Object.keys(obj as object)`; a key's value is `(key as { value?: unknown }).value` or `(obj as QsRecord)[key as PropertyKey]`. `normalizeStringifyOptions` declares `var format: FormatName` and casts `opts.arrayFormat as PropertyKey` and `as ArrayFormat`. `objKeys.sort(options.sort as (a: unknown, b: unknown) => number)`.
  - Every other line gained parameter and return types only.
  - Comments that are ours: the "Module dependencies" block in each file (what replaced `side-channel` and `es-define-property`, and how the files load each other), the note on `Channel` in `stringify.ts`, and the doc comments on the exported types.
- No function was renamed: the coverage report has no file with two functions of the same name (V8 names both exported functions `module.exports`, but they are in different files).
- The compiled `lib/qs/*.js` files match upstream's `lib/*.js` statement for statement (checked by stripping comments from both and formatting them with Biome) except for the `require` lines and channels above, `catch {}`, and TypeScript's `__esModule` marker, which lands on the `exports` object that `module.exports = ...` replaces.
- `src/utils.ts` loads it with `require('./qs') as import('./qs').Qs`.
